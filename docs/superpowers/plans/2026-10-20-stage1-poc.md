# Stage 1 — Drag Overlay PoC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove (or disprove) that a background menu-bar app can show its own drop-target panel during a Finder drag session when a modifier is held, and run a real action on drop.

**Architecture:** `DragMonitor` detects a drag session (global `leftMouseDown` + drag-pasteboard `changeCount` polled while the button is down) and resolves the mode from `NSEvent.modifierFlags` on a timer. `RadialMenuPanelController` owns one non-activating `NSPanel` whose content view is the drag destination; hit-testing goes through the pure `RadialLayout`. Everything the experiment needs to answer goes to `~/Library/Logs/Citra/poc.log`.

**Tech Stack:** Swift 6 (strict concurrency), AppKit + SwiftUI, ImageIO, Swift Testing, XcodeGen.

## Global Constraints

- Deployment target macOS 15.0, Swift 6 language mode, zero third-party dependencies.
- Project generated from `project.yml` by XcodeGen; never hand-edit `project.pbxproj`.
- No private API; no Accessibility / Input Monitoring unless the PoC proves it necessary.
- Mode priority when several modifiers are held: ⌘ (Conversion) > ⇧ (Tools) > ⌃ (File Actions).
- No modifier → no panel on screen (ordered out, not transparent), drag untouched.
- The original file is never modified; output goes next to it via temp file + rename, `name 2.ext` on collision.
- Force unwrap only with a comment explaining why it is safe.

## Review Focus

- Release over the center dead zone or outside the ring → drop refused, nothing happens.
- Modifier released mid-drag → panel ordered out so the underlying Finder window gets the drop.
- PNG with alpha → JPEG flattened on white, not black.
- Output name collision (`a.jpg` exists) → `a 2.jpg`, never overwrite.
- Cursor near a screen edge / secondary display → panel clamped into that screen's `visibleFrame`.

### Task 2: Pure logic + tests (TDD)

**Files:** `Citra/Drag/MenuMode.swift`, `Citra/Menu/RadialLayout.swift`, `Citra/Menu/PanelPlacement.swift`, `Citra/Actions/FileNaming.swift`, `CitraTests/*Tests.swift`.

**Produces:**
- `enum MenuMode { case conversion, tools, fileActions }`, `static func resolve(_ flags: NSEvent.ModifierFlags) -> MenuMode?`
- `struct RadialLayout { count, innerRadius, outerRadius, gap; func hitTest(_ p: CGPoint) -> Int?; func centerAngle(of:) -> Double; func sectorPath(_:) -> CGPath }` — `p` relative to center, y-up; sector 0 at 12 o'clock, clockwise. Gaps are not dead zones: a point is assigned by angle; `r < innerRadius` or `r > outerRadius` → nil.
- `enum PanelPlacement { static func frame(centeredAt:size:in:) -> CGRect }`
- `enum FileNaming { static func uniqueURL(directory:baseName:pathExtension:exists:) -> URL }` → `a.jpg`, `a 2.jpg`, …
- `enum DropOperation { static func choose(from mask: NSDragOperation) -> NSDragOperation }` — prefer `.copy`, `.generic`, `.link`, never `.move`/`.delete`.

- [ ] Write tests: mode priority (⌘⇧⌃ → conversion, ⇧⌃ → tools, ⌥ → nil); hit-test for n = 1, 2, 6, 9 incl. center, outside, gap points; placement inside / at each edge / oversize; naming free / taken / two taken; drop op for `.every`, `.generic`, `.link`, `.move`.
- [ ] Run → fail (types missing). Implement. Run → pass. Commit.
