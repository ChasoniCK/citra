# Feasibility: своё drop-окно поверх drag-сессии Finder

Статус на 2026-10-20: PoC собран, unit-тесты зелёные, **межпроцессный drag в GUI не проверен**.
Автоматическую проверку через computer use не делал — доступ к Finder отклонён. Все ответы ниже
помечены способом проверки: «SDK/документация», «покрыто тестом», «запуск», «не проверено».
После ручного прогона чек-листа раздел «Результаты» заполняется по `~/Library/Logs/Citra/poc.log`.

Окружение: macOS 27.0.1 (26A434), Xcode 27.1, один дисплей Q2722SVC 2560×1440 @2x.

## Ответы на вопросы из `core_risk`

### 1. Нужны ли разрешения?

- **Мышь:** глобальные мониторы мышиных событий не требуют разрешений — ограничение в документации `addGlobalMonitorForEvents` касается только key-событий. Open-source аналог NotchDrop делает то же самое (глобальные `leftMouseDown`/`leftMouseDragged`). *SDK/документация.*
- **Модификаторы:** `NSEvent.modifierFlags` (class) — состояние модификаторов «независимо от потока событий»; разрешений не требует. *Документация.*
- **Факт:** при запуске PoC пишет `accessibility trusted=false, input monitoring granted=false` — то есть приложение работает без обоих разрешений. *Запуск* (строка `launch:` в логе). Обновляются ли флаги во время чужого drag — **не проверено**.
- **Drag-пастборд:** в заголовке SDK 27 (`NSPasteboard.h`, `NSPasteboardAccessBehavior`): «The default behavior for the General pasteboard is to ask upon programmatic access. All other pasteboards default to always allow access.» Новый запрет на программное чтение пастборда к drag-пастборду не относится. *SDK.* Живое чтение во время drag Finder — **не проверено** (строка `session begin:`).
- **Escape через `keyState`:** может оказаться закрыт Input Monitoring. Если появится системный запрос — это результат эксперимента: разрешение не давать, опрос убрать, оставить только вариант (а).

### 2. Какую операцию вернуть, чтобы Finder не переместил и не удалил оригинал

AppKit сужает маску источника по модификатору: ⌃ → `link`, ⌥ → `copy`, ⌘ → `generic` (классическое Drag and Drop Programming Guide; на текущих сборках не подтверждено). ⇧ маску не меняет.
Решение в PoC: из маски берём первое из `copy` → `generic` → `link`; **`move` и `delete` не возвращаем никогда**, даже если других нет (тогда drop отклоняется). *Покрыто тестом* (`DropOperationTests`).

Ожидание: ⇧ → `copy` (зелёный «+», как на референсе), ⌘ → `generic` (стрелка без значка), ⌃ → `link` (стрелка алиаса). **Не проверено**; в логе — строка `source mask=… flags=… → op=…`.

Риск: если в маске Finder нет `generic`, при ⌘ маска окажется пустой, и drop на меню станет невозможен. Запасной вариант на этот случай: выполнять действие по отпусканию кнопки над сектором, по URL из drag-пастборда, а drop отклонять (Finder покажет анимацию возврата). Хуже по UX, но без приватных API.

Целостность оригинала после drop с ⌘ — **не проверено** (в чек-листе сверяется `shasum`).

### 3. ⌃ после начала drag

Эмуляция правого клика по ⌃ происходит только на `mouseDown`; посреди drag ⌃ лишь меняет флаги (и маску → `link`). **Не проверено** (сценарий F в чек-листе).

### 4. Окно появилось под курсором — приходит ли `draggingEntered` без движения мыши

**Не проверено.** В логе — строка `draggingEntered N ms after show, mouse moved since show: true/false`. На UX это почти не влияет: кольцо появляется центром под курсором, а центр — мёртвая зона, так что до выбора сектора курсор всё равно сдвинется.

### 5. Мульти-монитор, Retina, полноэкранное приложение, другой Space

- Позиционирование: окно центрируется на курсоре и сдвигается внутрь `visibleFrame` экрана под курсором (включая экраны с отрицательными координатами). *Покрыто тестом* (`PanelPlacementTests`).
- Hit-test идёт в точках окна (`draggingLocation` → координаты view), так что Retina на него не влияет. *Покрыто тестом* (геометрия); на живом Retina — **не проверено**.
- Мульти-монитор: на этой машине один дисплей — проверить нельзя.
- Полноэкранное приложение / другой Space: collection behavior выставлен — **не проверено**.

## Решения, принятые в PoC

- Приоритет режимов ⌘ > ⇧ > ⌃; ⌥ и Caps Lock игнорируются. *Покрыто тестом.*
- Центр кольца — мёртвая зона: отпустили там → drop отклонён, Finder возвращает файл, ничего не выполняется.
- Зазоры между секторами — только визуальные: точка в зазоре относится к сектору со своей стороны, поэтому подсветка не мигает при пересечении шва. *Покрыто тестом.*
- Отпускание вне кольца — обычный drop Finder (например, в другую папку — обычное перемещение Finder). Меню в нём не участвует.
