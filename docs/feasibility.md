# Feasibility: своё drop-окно поверх drag-сессии Finder

Окружение: macOS 27.0.1 (26A434), Xcode 27.1, один дисплей Q2722SVC 2560×1440 @2x.
Способ проверки помечен у каждого пункта: «GUI» (ручной прогон пользователем + `~/Library/Logs/Citra/poc.log`),
«тест» (unit-тест), «SDK» (заголовки/документация), «не проверено».
Автоматической проверки через computer use нет: доступ к Finder отклонён.

**Итог после прогонов 1–2 (2026-10-20): механизм работает.** Окно, показанное посреди drag Finder,
принимает drop, получает URL реально брошенного файла и выполняет действие, а оригинал не трогается.
Четыре бага поведения окна найдены и исправлены. Открыт один вопрос: видно ли кольцо
без движения мыши (оконный сервер окно показывает; ждём визуального подтверждения).

## Как устроен механизм

| Шаг | Реализация |
|---|---|
| Начало drag | Глобальный монитор `leftMouseDown` запоминает `NSPasteboard(name: .drag).changeCount`; пока кнопка зажата, таймер 60 Гц опрашивает `NSEvent.pressedMouseButtons`, `changeCount` и `NSEvent.modifierFlags`. `changeCount` изменился и на пастборде есть file URL → сессия началась. |
| URL до drop | `readObjects(forClasses: [NSURL], options: [.urlReadingFileURLsOnly: true])` на drag-пастборде. |
| Overlay | `NSPanel` `.borderless + .nonactivatingPanel`, level `.popUpMenu`, `.canJoinAllSpaces + .fullScreenAuxiliary + .stationary + .ignoresCycle`. Поверх `NSHostingView` лежит прозрачный `NSView`, зарегистрированный на `.fileURL`, — это drop-цель. |
| Конец drag | `pressedMouseButtons` стал 0. |
| Escape | Опрос `CGEventSource.keyState(.combinedSessionState, kVK_Escape)` → кольцо скрыто до отпускания кнопки. |

## Баги и что с ними сделано

1. **Кольцо не появлялось без движения мыши** (прогон 1, шаг 3).
   Исключено:
   - опоздание детекции: смена режима фиксируется сразу, без движения;
   - App Nap: зонд показал, что таймер 60 Гц 40 с без ввода идёт ровно, максимальный разрыв 18 мс;
   - H4 «оконный сервер не показывает окно во время drag»: в прогоне 2 окно становится видимым для сервера через 9–47 мс без движения.

   Осталась H5 «окно на экране, но SwiftUI не нарисовал содержимое». Без снимка экрана проверить её нельзя, поэтому нужен визуальный ответ в прогоне 3. Кроме того, в прогоне 1 видимость кольца ломал spring-loading (п. 2б), так что «не появилось» могло быть его следствием.

2. **Кольцо не открывалось повторно в том же drag.** Три причины, все исправлены:
   - **(а)** запоздалый `draggingExited` от предыдущего показа принимался за Escape. Эвристика удалена, Escape определяется опросом клавиши.
   - **(б)** AppKit **spring-loading**: когда drag задерживается над окном неактивного приложения, AppKit через ~1 с вызывает у него `makeKeyAndOrderFront` (`_NSSpringLoadingTrackingProc` → `-[NSWindow makeKeyAndOrderFront:]`, стек из прогона 2, 5 вызовов). Drag-сервер всё ещё считал скрытую панель целью, и она возвращалась на экран; отсюда `isVisible == true` после `orderOut` в прогоне 1. Панель теперь игнорирует `makeKeyAndOrderFront`. Покрыто тестом: без исправления он падал.
   - **(в)** `show()` полагался на `NSWindow.isVisible`; теперь состояние хранится в своём флаге `isShown`.

   Результат прогона 2: 24 нажатия модификатора из 24 открыли кольцо.

3. **Скрытое кольцо могло принять drop.** После скрытия кольца drag-сообщения продолжают приходить на панель, пока мышь не сдвинется (в прогоне 2 — 8 раз). Скрытое кольцо их отклоняет. Drop, пришедший через несколько миллисекунд после того, как опрос заметил отпускание кнопки (3 из 5 drop'ов прогона 1), по-прежнему принимается. Покрыто тестами, проверено мутацией.

## Эксперимент Fade (прогон 2)

Окно упорядочивается при старте любого file drag невидимым (`alphaValue = 0`, `ignoresMouseEvents = true`), а показ кольца меняет только прозрачность.
- Повторное открытие работает.
- В 5 drag'ах без модификатора ни одно drag-сообщение не пришло в невидимое окно; файл переместился в `Folder A` обычным образом. Похоже, drag проходит сквозь окно с `ignoresMouseEvents`, но это недокументированное поведение, и не известно, пересекал ли курсор область окна.

Вывод: если в прогоне 3 кольцо видно без движения и в обычном режиме, Fade не даёт преимуществ, а риск для сценария E (drag без модификатора) несёт. Тогда эксперимент удаляется.

## Решения, принятые в PoC

- Приоритет режимов ⌘ > ⇧ > ⌃; ⌥ и Caps Lock игнорируются (тест).
- Центр кольца — мёртвая зона: отпустили там → drop отклонён, Finder возвращает файл.
- Зазоры между секторами только визуальные: точка в зазоре относится к сектору со своей стороны (тест).
- Отпускание вне кольца — обычный drop Finder; меню в нём не участвует.
