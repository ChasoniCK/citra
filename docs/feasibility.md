# Feasibility: своё drop-окно поверх drag-сессии Finder

Окружение: macOS 27.0.1 (26A434), Xcode 27.1, один дисплей Q2722SVC 2560×1440 @2x.
Способ проверки помечен у каждого пункта: «GUI» (ручной прогон пользователем + `~/Library/Logs/Citra/poc.log`),
«тест» (unit-тест), «SDK» (заголовки/документация), «не проверено».
Автоматической проверки через computer use нет: доступ к Finder отклонён.

**Итог после прогона 1 (2026-10-20): механизм работает.** Окно, показанное посреди drag Finder,
принимает drop, получает URL реально брошенного файла и выполняет действие, а оригинал не трогается.
Найдены три бага поведения окна, два исправлены, по третьему собраны данные для прогона 2 (см. ниже).

## Как устроен механизм

| Шаг | Реализация |
|---|---|
| Начало drag | Глобальный монитор `leftMouseDown` запоминает `NSPasteboard(name: .drag).changeCount`; пока кнопка зажата, таймер 60 Гц опрашивает `NSEvent.pressedMouseButtons`, `changeCount` и `NSEvent.modifierFlags`. `changeCount` изменился и на пастборде есть file URL → сессия началась. |
| URL до drop | `readObjects(forClasses: [NSURL], options: [.urlReadingFileURLsOnly: true])` на drag-пастборде. |
| Overlay | `NSPanel` `.borderless + .nonactivatingPanel`, level `.popUpMenu`, `.canJoinAllSpaces + .fullScreenAuxiliary + .stationary + .ignoresCycle`. Поверх `NSHostingView` лежит прозрачный `NSView`, зарегистрированный на `.fileURL`, — это drop-цель. |
| Конец drag | `pressedMouseButtons` стал 0. |
| Escape | Опрос `CGEventSource.keyState(.combinedSessionState, kVK_Escape)` → кольцо скрыто до отпускания кнопки. |

## Баги прогона 1 и что с ними сделано

1. **Кольцо не появляется без движения мыши после нажатия модификатора** (ответ пользователя на шаг 3).
   Что исключено:
   - опоздание детекции: смена режима логируется сразу, без движения;
   - App Nap: отдельный зонд показал, что таймер 60 Гц 40 с без ввода идёт ровно, максимальный разрыв 18 мс.

   Остаются две гипотезы:
   - H4: во время drag оконный сервер не показывает только что упорядоченное окно до следующей переоценки цели drag;
   - H5: окно на экране, но SwiftUI не рисует содержимое до первого drag-сообщения.

   Для прогона 2 добавлено: лог `occlusionState` через 100/500/1500 мс после показа; эксперимент «Fade» (пункт в меню) — окно упорядочивается при старте drag невидимым и click-through, а показ меняет только `alphaValue`.

2. **После первого показа кольцо больше не открывается в этом же drag.** Две причины, обе видны в логе:
   - **(а)** запоздалый `draggingExited` от предыдущего показа приходил сразу после повторного показа, и эвристика «exit, а курсор внутри диска — значит Escape» глушила кольцо до отпускания кнопки. Эвристика удалена; Escape теперь определяется опросом клавиши.
   - **(б)** после `orderOut` AppKit дважды вернул `isVisible == true`, хотя `orderFront` никто не вызывал, и `show()` молча ничего не делал. Теперь состояние хранится в своём флаге `isShown`, а любое упорядочивание окна не из контроллера пишется в лог со стеком вызовов. Откуда берётся `isVisible == true`, пока не установлено.

3. **Найдено по логу:** после скрытия кольца (отпустили модификатор) drag-сообщения продолжают приходить на скрытую панель, пока мышь не сдвинется. Отпусти пользователь кнопку в этот момент — выполнилось бы действие невидимого сектора. Теперь скрытое кольцо отклоняет такие сообщения и drop. При этом drop, пришедший через несколько миллисекунд после того, как опрос заметил отпускание кнопки (так было в 3 из 5 drop'ов прогона 1), по-прежнему принимается. Оба случая покрыты тестом и проверены мутацией: при возврате старого поведения тесты падают.

## Решения, принятые в PoC

- Приоритет режимов ⌘ > ⇧ > ⌃; ⌥ и Caps Lock игнорируются (тест).
- Центр кольца — мёртвая зона: отпустили там → drop отклонён, Finder возвращает файл.
- Зазоры между секторами только визуальные: точка в зазоре относится к сектору со своей стороны (тест).
- Отпускание вне кольца — обычный drop Finder; меню в нём не участвует.
